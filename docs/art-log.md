# 美术迭代记录

每一步改动都留一组「固定机位 × 固定时刻」的对照图，数值来自 `tools/diff.py`。
所有像素差都是相对**旧栈 http 基线**（`tools/base-http/`，three r159 + 原生 `<script>`）算的。

复现方式：

```bash
npm run build
cd dist && python -m http.server 8081 &
SHOT_BASE=http://127.0.0.1:8081/index.html bash tools/shots.sh tools/now 960 540
python tools/diff.py tools/base-http tools/now tools/diffs 6
```

## P1 迁移技术栈（Vite + ESM + three r187）

不改画面。九张对照 meanDiff 0.23–0.80/255、可见差异像素 ≤1.75%（阴影滤波与约一级全局色调）；
同一构建重复截图逐位相同（0.000 / 0.00%），说明对照流程本身可复现。

顺带修掉的真实缺陷：

- `?ui=0` 时载入遮罩永不消失（`reveal` 被替换成空函数）；
- 66 头牛的 GLTF 分支在迁移后整段失效（`window.FL_COW` 与轮询没替换），差点整场没牛；
- `PCFSoftShadowMap` 在 r187 已移除，会被静默降级。

## P2 天空 / 大气 / 光比

### P2.1 天空穹顶：顶点色 → 逐像素 shader

- 穹顶改成 `ShaderMaterial`：竖直三段梯度 + 地平线暖带 + 日/月晕 + 薄云（fbm）+ 地平线下地气。
- 曾经退回顶点色的原因是**某个自定义 shader 在 ANGLE 上整片发黑**——真实原因是 `pow()` 底数为负得到 NaN。
  这一版所有 `pow` 的底数先夹到非负（`max(x, 0.0)`），截图走真实 GPU 后端，没有再出现。
- 云量按 `smoothstep(0.58, 0.86, fbm)` 压覆盖率：fbm 均值在 0.5 附近，下限给低了整片天会糊上一层灰
  （第一版就是这样，正午的天空变成一块脏灰绿）。

### P2.2 光比：1.9:1 → 3.2:1（正午 4.9:1）

daycycle 里三套配色改成统一的三段混合 `mix3(night, dusk, day)`，权重 `nightF` / `duskMix`：

| | 夜 | 黄昏 | 白天 |
| --- | --- | --- | --- |
| 主光（同一盏 DirectionalLight，夜里是月亮） | 6.6 | 5.4 | 9.4 |
| HemisphereLight | 2.0 | 1.05 | 1.15 |
| 暖补光 | 1.4 | 0.95 | 0.42 |
| 侧补光 | 1.2 | 0.60 | 0.34 |
| **主光 : 环境** | 1.4 : 1 | **3.2 : 1** | **4.9 : 1** |

曝光同步下调（夜 1.34 / 黄昏 1.06 / 白天 0.96），否则主光提亮后会整体过曝。

### P2.3 晨昏窗口：18:20 的太阳只有 17°，原来已经不算"黄昏"

原来的 `duskF` 窗口是 `1 - |sin| / 0.24`，太阳高度角 17° 时（页面默认这一刻）已经衰减到 0，画面停在
「白天蓝 + 一点粉」的灰调上。窗口放宽到 `/0.30`（`duskMix` 到 `/0.60`）后，18:20 才真的落在金色区间。

### P2.4 颜色混合：蓝 + 橙在 RGB 里插值会经过灰色

地平线色由「白天蓝」和「黄昏橙」线性插值得到，中段必然经过灰——18:20 的天空就是这么变成"灰粉"的。
在过渡中段按 `1 + 0.85 × 4·duskMix·(1-duskMix)` 保亮度提饱和（两端不动、中点最强），色相被拉回来。

### P2.5 雾：FogExp2 → 线性 Fog

`FogExp2(0.0016)` 在 400 m 处就吃掉一半反差，而场景本体只有 254 m——整个场地都被罩灰。
改成 `THREE.Fog(color, near, far)`，`near` 从 300 m 起算（场地本体几乎不受影响），`far` 随昼夜 2100 → 1250 m；
雾色改成与「看向地平线时的天空色」一致，否则远景和天空之间会有一条缝。

## P3 远景地形（`src/terrain.js`）

### 判据

P2 收尾时留下的问题已经被量化：18:20 的 overview 里，画面**上半部分没有任何几何体**，
只有一片被雾吃平的天空色。相机在 (154, 258, 188)、俯角 45°、fov 36°，
画面上边缘的视线是 27° 俯角，落在离相机约 500 m 的地面上——
所以「远景」不是画一座 5 km 外的山，而是把**场界外 100–500 m 这一圈**填满。

### 做法

- **近场地形**：2600×2600 m 的平面，y = -0.45（比地台顶面 -0.1 低 35 cm，场地成一块矮台）。
  贴图 2048²、1.27 m/px，全部 canvas 程序化绘制：
  方田（每 380–640 m 一条防护林）→ 条田（28–83 m 宽的窄带，横竖随机）→ 田埂与机耕路
  → 沿方田界线成排的杨树暗点 → 地面噪点 → 村落小色块。
  进场道路从西门 (x=-127, z=56) 往外接到县道，另外画了南北两条便道。
- **边缘径向淡出**：贴图在半径 780 m 开始做 alpha 渐隐（`destination-in` + 径向渐变），
  1300 m 处完全透明，交给 7000×7000 m 的远场底盘接住，避免「近场贴图边缘一刀切」。
- **远场底盘**：7000 m 平面、纯色 + 雾，在 2100 m 之外被雾吃成全雾色。
- **地平线无缝**：`daycycle` 里把 `sky.setLand(cFog)` 用雾色直接喂给天空球的地平线以下颜色，
  远处地形与天空因此同色，不会有一条缝。
- **近处几何**：场界外一圈杨树防护林（9 m 间距、毛白杨的窄高冠三层锥体）+ 西北与东南两处村庄
  （院墙、红砖正房、灰瓦顶、院内杨树）。几何体不进阴影、`<5000` 三角面。
- 相机 `far` 3400 → 20000，天空球半径 1200 → 9000（远场底盘要落在穹顶里面）。

### 踩过的坑

- `terrain.js` 一开始 `import { U } from './utils.js'`，但 utils 并不导出 `U`，而是挂在 `FL.U` 上，
  模块加载直接 SyntaxError，`FL.createTerrain` 是 undefined——被 `if (FL.createTerrain)` 静默跳过，
  画面一点变化都没有。**改了模块要回头看 console 的 `Uncaught SyntaxError`。**
- 第一版调色盘太暖，整幅画面（天空暖 + 地面暖 + 夕照暖）糊成一片橙；
  压暗一档后又变成一片深褐、田块纹理全丢。最后取「去掉红色、偏灰橄榄」的中间值，
  并用材质 `color` 做整体压暗而不是改每一格颜色（改调色盘会同时丢掉田块的明暗节奏）。
- 远场底盘曾经复用近场贴图平铺 2.6×，结果背景出现一片巨大的红灰色块（村落像素被放大），
  改回纯色 + 雾。

### 结果

九张对照见 `tools/p3-terrain`。与 `tools/p2-final` 相比，变化集中在 overview 的上半部分：
地平线不再是纯色，而是被条田和防护林填满，地台边缘与地面之间有了接触阴影，
场地从"浮着的板"变成"坐在地里的一座场"。
