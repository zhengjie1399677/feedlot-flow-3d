每一步改动都留一组「固定机位 × 固定时刻」的对照图，数值来自 `tools/diff.py`。
所有像素差都是相对**旧栈 http 基线**（`tools/base-http/`，three r159 + 原生 `<script>`）算的。

```bash
npm run build
cd dist && python -m http.server 8081 &
SHOT_BASE=http://127.0.0.1:8081/index.html bash tools/shots.sh tools/now 960 540
python tools/diff.py tools/base-http tools/now tools/diffs 6
```

不改画面。九张对照 meanDiff 0.23–0.80/255、可见差异像素 ≤1.75%（阴影滤波与约一级全局色调）；

## P2 天空 / 大气 / 光比

### P2.1 天空穹顶：顶点色 → 逐像素 shader

- 穹顶改成 `ShaderMaterial`：竖直三段梯度 + 地平线暖带 + 日/月晕 + 薄云（fbm）+ 地平线下地气。
- 曾经退回顶点色的原因是**某个自定义 shader 在 ANGLE 上整片发黑**——真实原因是 `pow()` 底数为负得到 NaN。
  这一版所有 `pow` 的底数先夹到非负（`max(x, 0.0)`），截图走真实 GPU 后端，没有再出现。
- 云量按 `smoothstep(0.58, 0.86, fbm)` 压覆盖率：fbm 均值在 0.5 附近，下限给低了整片天会糊上一层灰
  （第一版就是这样，正午的天空变成一块脏灰绿）。

### P2.2 光比：1.9:1 → 3.2:1（正午 4.9:1）

daycycle 里三套配色改成统一的三段混合 `mix3(night, dusk, day)`，权重 `nightF` / `duskMix`：

| | 夜 | 黄昏 | 白天 |
| --- | --- | --- | --- |
| 主光（同一盏 DirectionalLight，夜里是月亮） | 6.6 | 5.4 | 9.4 |
| HemisphereLight | 2.0 | 1.05 | 1.15 |
| 暖补光 | 1.4 | 0.95 | 0.42 |
| 侧补光 | 1.2 | 0.60 | 0.34 |
| **主光 : 环境** | 1.4 : 1 | **3.2 : 1** | **4.9 : 1** |

曝光同步下调（夜 1.34 / 黄昏 1.06 / 白天 0.96），否则主光提亮后会整体过曝。

### P2.3 晨昏窗口：18:20 的太阳只有 17°，原来已经不算"黄昏"

原来的 `duskF` 窗口是 `1 - |sin| / 0.24`，太阳高度角 17° 时（页面默认这一刻）已经衰减到 0，画面停在
「白天蓝 + 一点粉」的灰调上。窗口放宽到 `/0.30`（`duskMix` 到 `/0.60`）后，18:20 才真的落在金色区间。

### P2.4 颜色混合：蓝 + 橙在 RGB 里插值会经过灰色

地平线色由「白天蓝」和「黄昏橙」线性插值得到，中段必然经过灰——18:20 的天空就是这么变成"灰粉"的。
在过渡中段按 `1 + 0.85 × 4·duskMix·(1-duskMix)` 保亮度提饱和（两端不动、中点最强），色相被拉回来。

### P2.5 雾：FogExp2 → 线性 Fog

`FogExp2(0.0016)` 在 400 m 处就吃掉一半反差，而场景本体只有 254 m——整个场地都被罩灰。
改成 `THREE.Fog(color, near, far)`，`near` 从 300 m 起算（场地本体几乎不受影响），`far` 随昼夜 2100 → 1250 m；
雾色改成与「看向地平线时的天空色」一致，否则远景和天空之间会有一条缝。

## P3 远景地形（`src/terrain.js`）

### 判据

P2 收尾时留下的问题已经被量化：18:20 的 overview 里，画面**上半部分没有任何几何体**，
只有一片被雾吃平的天空色。相机在 (154, 258, 188)、俯角 45°、fov 36°，
画面上边缘的视线是 27° 俯角，落在离相机约 500 m 的地面上——
所以「远景」不是画一座 5 km 外的山，而是把**场界外 100–500 m 这一圈**填满。

### 做法

- **近场地形**：2600×2600 m 的平面，y = -0.45（比地台顶面 -0.1 低 35 cm，场地成一块矮台）。
  贴图 2048²、1.27 m/px，全部 canvas 程序化绘制：
  方田（每 380–640 m 一条防护林）→ 条田（28–83 m 宽的窄带，横竖随机）→ 田埂与机耕路
  → 沿方田界线成排的杨树暗点 → 地面噪点 → 村落小色块。
  进场道路从西门 (x=-127, z=56) 往外接到县道，另外画了南北两条便道。
- **边缘径向淡出**：贴图在半径 780 m 开始做 alpha 渐隐（`destination-in` + 径向渐变），
  1300 m 处完全透明，交给 7000×7000 m 的远场底盘接住，避免「近场贴图边缘一刀切」。
- **远场底盘**：7000 m 平面、纯色 + 雾，在 2100 m 之外被雾吃成全雾色。
- **地平线无缝**：`daycycle` 里把 `sky.setLand(cFog)` 用雾色直接喂给天空球的地平线以下颜色，
  远处地形与天空因此同色，不会有一条缝。
- **近处几何**：场界外一圈杨树防护林（9 m 间距、毛白杨的窄高冠三层锥体）+ 西北与东南两处村庄
  （院墙、红砖正房、灰瓦顶、院内杨树）。几何体不进阴影、`<5000` 三角面。
- 相机 `far` 3400 → 20000，天空球半径 1200 → 9000（远场底盘要落在穹顶里面）。

### 踩过的坑

- `terrain.js` 一开始 `import { U } from './utils.js'`，但 utils 并不导出 `U`，而是挂在 `FL.U` 上，
  模块加载直接 SyntaxError，`FL.createTerrain` 是 undefined——被 `if (FL.createTerrain)` 静默跳过，
  画面一点变化都没有。**改了模块要回头看 console 的 `Uncaught SyntaxError`。**
- 第一版调色盘太暖，整幅画面（天空暖 + 地面暖 + 夕照暖）糊成一片橙；
  压暗一档后又变成一片深褐、田块纹理全丢。最后取「去掉红色、偏灰橄榄」的中间值，
  并用材质 `color` 做整体压暗而不是改每一格颜色（改调色盘会同时丢掉田块的明暗节奏）。
- 远场底盘曾经复用近场贴图平铺 2.6×，结果背景出现一片巨大的红灰色块（村落像素被放大），
  改回纯色 + 雾。

### 结果

九张对照见 `tools/p3-terrain`。与 `tools/p2-final` 相比，变化集中在 overview 的上半部分：
地平线不再是纯色，而是被条田和防护林填满，地台边缘与地面之间有了接触阴影，
场地从"浮着的板"变成"坐在地里的一座场"。

## P4 材质与光照修正（含线上反馈的五条问题）

### 1. 雾把主体也吃掉了（线上反馈）
`three` 的雾按**相机深度**算，而 overview 机位离场地 300–600 m，正好落在 `fog.near` 之后——镜头一拉远，场地自己先被雾糊住。

改法：雾的起点按相机距离推出去，`fog.near = max(时段下限, 相机距离 + 240)`，远端长度保持各时段设定值（1150/1450/2000）。`src/effects.js` 的相机 rig 新增 `get dist()`，`src/main.js` 每帧用 `phase.fogSpan` 重算。效果：任何机位下场地本体都在雾外，只有远景褪色。

### 2. 场地草坪像"布块"（线上反馈）
原来 `flatRound(..., uvTile=10)` 让 512² 贴图每 10 m 平铺一次，252 m 的草坪上有 25 个完全相同的图案。

改法：`src/utils.js` 新增 `lawn()`（1024²，大尺度干枯/深绿斑块 + 中尺度草簇裸土 + 42000 个噪点 + 四道压秃的土路），整块只铺一次不平铺；`flatRound` 的 `uvTile` 传 0 时按包围盒把 uv 归一到 0..1。

### 3. 出场道路断头（线上反馈）
场内东侧道路在 `(112, 96)` 穿出北栅栏，场外没有任何路面接着，空车开出去就是悬在田里。

改法：`src/terrain.js` 的 `paintRoads` 增加东北角出场道路（`(112,96) → (116,200) → (128,420) → (168,760)` 的贝塞尔），与场内出口对齐、同宽 11 m。

### 4. 两车重叠（线上反馈）
`src/vehicles.js` 的 `followSpeed` 只在前车落在 `LANE=3.3` 的侧向容差内才减速，而侧向偏移是**按本车车头方向**算的：两车从不同路线斜切进同一个路口时，夹角把横向距离放大到 3.8 m 以上，于是互相"看不见"，直接插到一起（实测 `cattle(112,-59)` 与 `out(109,-69)` 重叠 3.3 m）。

改法：保留同车道跟车逻辑，另加一条按距离兜底的规则——对方在车头方向 `cos > 0.55` 的扇区内、距离小于 `max(SCAN, 车身和/2 + FOLLOW + 20)` 就停。`+20` 是制动距离：10 m/s 配 `DEC 3.3` 需要约 16 m，原来的 6 m 根本刹不住。

验证：`?dbg=1` 会扫描所有车对、把重叠写进 `data-overlap`；t=0…152 每 8 s 采样一遍，全部 `none`。

### 5. 环境贴图跟着昼夜走
原来 `FL.createEnvironment` 启动时烘一张**夜景** PMREM 就不管了，正午玻璃和金属反射的全是夜空。

改法：改成按当前天光颜色现烘（256×128 equirect），颜色变化超过阈值才重烘（整轮昼夜约 20 次，每次几毫秒）。`daycycle` 在 `sky.setSky()` 之后调 `FL.env.update(cTop, cMid, cHor, cGlow, azVec)`。顺带把黄昏/黎明曝光从 1.06 抬到 1.18（去掉主体雾之后这两个时段整体变暗了一档）。

对照图：`tools/p4-fix/sheet.png`（9 格）。

## P5 开源素材接入（HDRI / PBR / Kenney 车辆）

**判断**：材质救不了形状，但反过来形状也救不了"塑料感"——两条腿一起走。这一轮先用现成 CC0 资产把"材质"和"道具"补齐，形状留给下一轮（牛舍差异化、倒角、细节件）。

### 1. 环境光换成真实全景图

- 原状：`FL.createEnvironment` 启动时烘一张手绘的夜景 PMREM 就不管了，正午玻璃反射的全是夜空。
- 做法：Poly Haven 的 Qwantani 地点四个时段（晨 / 午 / 黄昏 / 夜）1K HDR，用 `tools/hdr_min.py` 自写 RGBE 读写降到 256×128（131 KB/张），按 `daycycle` 算出的权重切 key。
- **关键数**：HDRI 一旦当 `scene.environment`，环境光会被抬一大截。整图均值实测 123 → 强度 0.9 时 160、0.38 时 141、0.16 时 132、0.09 时 128。最终 **`INTENSITY = { dawn: 0.05, day: 0.10, dusk: 0.035, night: 0.08 }`**——IBL 只负责玻璃/金属的反射，漫反射补光仍归半球光和主光。
- 结果：黄昏时办公楼玻璃出现真实反光，不再是一块死灰。

### 2. PBR 贴图（ambientCG，CC0）

- 四套：`Concrete034`（地坪/场地）、`Asphalt033`（路面/停车场）、`CorrugatedSteel009`（彩钢瓦）、`PaintedPlaster017`（抹灰墙）。
- `tools/tex_prep.py` 抽出 color / normal / rough / ao，统一 512²，共 15 张 760 KB。
- `U.surface(name)` 载入，`U.boxUV(geo, w, h, d, tile)` 按六个面各自的尺寸重算 uv——**这是关键**：原来所有盒子的 uv 都是 0..1，40 m 的墙和 2 m 的箱子纹理密度差 20 倍，看着哪哪都不对。
- **调色踩了三轮坑**：①原始 tint 太亮（apron `0xb9bdbd`）→ 场地均值 128.5 → 169.5，整幅发白；②压暗后偏土黄，因为 ambientCG 的混凝土 albedo 本身就偏暖，暖光乘暖图必糊；③解法是**把 albedo 去色**（混凝土 k=0.88、抹灰 0.6、沥青 0.5），色相全部交给材质 `color`；④混凝土 tint 最后定成偏蓝的 `0x77848e`，黄昏暖光下才读成水泥地而不是黄泥地。
- 结果：正午地坪是浅灰混凝土、路面是沥青、屋面是带肋的红彩钢，同一块面积上的材质不再靠颜色区分而是靠粗糙度和法线。

### 3. 停车场的车换 Kenney

- 原状：38 个圆角盒子拼的车，`paints` 用的是墙面/镀锌/红/蓝几种材质轮转，整片停车区比场地本体还抢眼。
- 做法：Kenney Car Kit（CC0）取 7 个车型，GLB 里贴图引用改成本地 `colormap.png`，`colormap.png` 降饱和到 32%、压暗到 86%，材质再乘一层 `0xb9b6b0`。
- **两个坑**：①改 GLB 时把第一个 chunk 的类型写成了 `BIN` 而不是 `JSON`，`GLTFLoader` 报 `JSON content not found`，七辆车一辆都没出来（而且 `onError` 被吞掉，看控制台也干净的）；②Kenney 车模的长轴是 z，直接套原来盒子车的 ±90° 旋转会让车横在车位里，得改成 0 / π。
- 结果：形状、车窗、车灯、轮子都对，颜色也压住了，默认机位下不再抢戏。

### 仍然没做

- 六栋牛舍还是一模一样（`src/layout.js:64-73` 六栋参数只有 `cx` 和 `mirror`）；单体信息量也低：没有立柱、勒脚、檐口、雨落管、屋面设备，全是硬边直角。
- 牛在默认全位面仍然只有几个像素。
- 黄昏整幅偏暖偏闷，还没调回来。

## P6 办公楼与交易中心：从"平房"做到"门脸"

**先查了外部素材，结论是不该换**：Poly Haven 521 个模型里只有 `modular_factory_facade`、`modular_urban_apartments_facade` 两种立面模块（工业厂房/公寓，风格对不上），Kenney / Quaternius 是卡通低模，放进写实低模的场区里立刻穿帮。**中国育肥场的彩钢瓦牛舍、交易大厅、员工办公楼在这类 CC0 库里没有对应物**，这两栋还是得自己生成——但可以生成得更像样。

### 做法（不是重写，是把"体量"和"立面"两件事补上）

- **员工办公楼**：三层 10.6 m → 五层 17.4 m；中部塔楼 14.6 m → 22.0 m；门厅从两根圆柱换成四柱门廊 + 三级台阶 + 加宽雨棚。
  - 立面推倒重来：原来每跨一个小窗洞 + 暖光贴片，五层排下来整体像宿舍楼；改成**首层石材基座 + 二至五层连续玻璃幕墙**，幕墙带竖向分格（12 跨）、上下层间压条、檐口压顶。
  - 新材质 `M.curtain`：`0x5a6b78 / roughness 0.34 / metalness 0.06 / envMapIntensity 2.0`。原来的 `M.glass` 是纯镜面（`0x0c161d`, metalness 0.9），在环境光只有 0.10 的场景里整面墙直接发黑——**金属度高的材质在弱 IBL 下就是黑洞**，这是这一轮最容易踩的坑。
- **活牛交易中心**：主体 11.2 m → 14.6 m；柱廊由六柱加到八柱、柱高 7.0 → 9.4 m；入口中庭 10.4 → 13.4 m；南立面幕墙分成上下两段、中间加一道石材横带；台基从三阶加到四阶。
- 屋顶招牌、行情立牌、柱廊灯池等原有细节全部保留，只跟着高度重新定位。

### 结果

两栋楼在默认机位上从"平房"变成"有门脸的公共建筑"：办公楼是深灰玻璃盒子，交易中心是带柱廊的浅色石材体量。**没有引入任何新素材**，改动全部在 `src/buildings.js` 与 `src/world.js`。

## P7 品牌换装与第一人称跟车（2026-11）

这一轮四件事：公司名改成**草都草牧业股份有限公司**（可缩写）；牛舍改蓝；TMR 罐子改白；加一个固定在车上、平视看园区的第一人称跟车。

### 品牌：门头用缩写，楼顶用全称

- 门头 13.5 m 宽的牌子是园区第一眼，写「草都草牧业 · 育肥一场 / CAODU GRASS & LIVESTOCK · UNIT 01」；员工楼顶 17 m 宽的牌子放全称「草都草牧业股份有限公司 / CAODU GRASS ANIMAL HUSBANDRY CO., LTD.」。页面眉标、h1、遮罩和 README 同步改成草都草牧业。
- 文字贴图是固定 1024 宽的 canvas，`sign()` 只按牌面比例算画布高，**不会自动缩字号**。全称 11 个汉字在 78 px 下占 858 px，能放下；再大就会顶到画布边缘。以后改招牌先数字数，别让字被裁掉。

### 牛舍变蓝：新增专用材质，不动共用材质

- `M.wall` / `M.roof` 被园区其它建筑共用，直接改会把它们一起染蓝。新增 `M.barnWall`（PaintedPlaster017，`0x7ba0bc`）、`M.barnRoof`（CorrugatedSteel009，`0x3f6f9e`）、`M.barnRoofSouth`（`0x35608b`），只给 `buildBarn` / `gableWall` 用。
- 屋面用饱和一点的钢蓝，墙面用浅蓝灰：俯视时蓝屋顶最显眼，墙面如果再纯蓝，六栋牛舍会糊成一整片蓝色，和灰色场地、暖色木饰也分不开。南北两排保留一深一浅，剖视仍然走原来的 roofKit，蓝屋顶自动跟随半透明。
- 结果：日景俯视里牛舍从"棕红屋顶 + 米色墙"变成"蓝色彩钢 + 浅蓝墙"，和整个场区的灰、绿、暖黄拉开了。

### TMR 白罐：车上的和场里的都改

- 新增 `M.tmrWhite`（`0xf0f1ea`，roughness 0.38，metalness 0.22），替换三只原料筒仓、两只成品日粮仓的筒身 / 锥斗 / 顶盖，TMR 车搅拌罐 `mix` 同色。加强环、爬梯、支架仍是镀锌钢，白罐不会变成没有细节的白模。
- 用户说的"TMR 的罐子"可能指车上的搅拌罐，也可能指配料中心的白筒仓；两处一起改白，语义覆盖完整，也形成"原料—成品—车"的颜色呼应。

### 第一人称跟车：给同一个 rig 加模式

- 没有新开一套相机，而是在 `FL.createCameraRig(camera, dom, fleet)` 里加 ride 子系统：相机固定在所选车辆的驾驶室眼位，退出时恢复原来的轨道机位、FOV 36、近裁面 4。
- `RIDE_CFG` 给四台车各一个局部眼位（约 `y 2.42–2.5`、`z 5.35–5.45`），用 `atan2(hx, hz)` 跟随车头方向；不跟 roll / pitch，只做轻微起伏，避免过坎时镜头晃吐。进入时 FOV 36 → 58、near 4 → 1.2，否则近处的车头会被裁掉。
- 操作：拖拽转头（yaw ±2.75 rad、pitch −0.62..0.55）、滚轮 FOV 42–72、双击回正、`1`–`4` 或 `←` / `→` 换车、`C` / `Esc` 退出。右上角视角条下方加跟车入口；跟车时入口位置换成紧凑 HUD，显示当前车名、四车短标签和 `C 退出`，操作提示在左下角 `.hint-ride`。
- **一个只有进车才暴露的坑**：`Object3D.lookAt` 是 +Z 朝目标，相机 lookAt 是 -Z 朝目标。一开始 helper 用了 `Object3D`，镜头进车后直接朝后看；换成 `PerspectiveCamera` 才对。
- **另一个坑**：跟车入口的 `.ride-launch` 背景被 `.views button` 的透明样式覆盖，必须写成 `.views .ride-launch` 才能立起来；active 色也被 `.views button.on` 的琥珀压住，用同样提高优先级的方式改成青色。
- 取舍：驾驶室壳体从内部看会被背面剔除，实际留下的是**引擎盖 + 平视视野**，像把镜头绑在车上，而不是驾驶模拟。没有伪造仪表盘，也不做车辆物理；HUD 和四车切换负责告诉用户"现在在谁车上"。

## P8 场外草甸与跟车视点抬高（2026-11）

用户觉得场外土默川农田和园区的画风差异太大，问能不能把外面也铺成园区这种草地；同时指出跟车截图里 TMR 的绿色引擎盖挡住了视线。

### 场外草甸

- `paintFields` 在条田/林带画完、噪点和村庄之前叠一层 `paintMeadow`：620m 半径、400m 内实、往外软过渡，盖住近处条田，只把 620–780m 的一圈农田和远处村庄/防护林留给地平线。道路在 `paintRoads` 里后画，所以进出场道路仍然压在草上。
- 配方：草绿底 + 大小不一的深浅斑 + 少量干草斑 + 斜向低对比割草带 + 12000 个细碎草屑；最后用径向渐变做软边。不是整片纯色，避免俯视像一张绿桌面。
- `mats.ground` 的 tint 从 `0xb2ae9e` 调到 `0xbfc0a8`，`mats.far` 从土灰调到草绿灰 `0x7b8168`；草地上没有新增 3D 草，仍是一张 2048 贴图，只在生成时多合成一次 canvas，运行期 draw call / 几何量不变。代价是弱化了“秋收农田”的地域身份，近处更像园区草坪；远处条田和林带还在，保留地平线层次。

### 跟车视点

- 四车眼位从 `2.42–2.5m` 抬到 `2.68–2.7m`，并前移 0.2–0.3m（TMR 眼位 `2.7m`、`z=5.65`）；默认 pitch 从 `-0.035`（略低头）收到 `0`（水平），双击回正也回水平。引擎盖从原来挡住画面中部降到只占下沿一条，仍保留引擎盖作为“在车上”的框景，没有隐藏车辆。
- 验证：1600×900 日景/黄昏重新截图，TMR 跟车视野中心不再被绿色盖住；`?ride=forage` 等其他车正常。最终构建 JS 802.55 kB / gzip 218.10 kB、CSS 12.04 kB。
